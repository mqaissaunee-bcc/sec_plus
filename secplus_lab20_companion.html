📋 Overview

Least privilege, implemented.

Access control on Linux comes down to who (users and groups) and what they may do (file permissions). You'll create a group and users, set passwords, and then control file access two ways: symbolic (u/g/o and +/-rwx) and absolute (octal, like chmod 764). The thread is least privilege — give each account exactly the access it needs and no more.

[THE ONE IDEA] Every Linux permission answers two questions: who (owner / group / others) and what (read / write / execute). Read rwxrw-r-- as owner-group-others and the whole model clicks.

⚠️ Where students get stuck

The permission math that trips people.

[OCTAL MATH] r=4, w=2, x=1; add them per class. 7=rwx, 6=rw-, 5=r-x, 4=r--. 764 is owner 7 / group 6 / others 4.
[READING ls -l] The 10 characters are: type, then owner (3), group (3), others (3). -rwxrw-r-- is a file, owner rwx, group rw-, others r--.
[DIRECTORIES NEED x] To cd into a directory you need execute on it, not just read. 'Permission denied' entering a folder is usually a missing x.
[passwd ≠ /etc/passwd FOR HASHES] /etc/passwd lists accounts; the password hashes are in /etc/shadow. Don't expect to see passwords in passwd.
[SYMBOLIC vs ABSOLUTE] They do the same job differently — symbolic nudges specific bits, absolute sets the full set. Mixing up u+r with an octal digit is a common slip.

🛡️ The defender's view

This is identity and access management at the host level.

Least privilege

Breaks: over-broad access

Give each user and file only the access required. Tight permissions (and not making everything world-readable/writable) is the everyday expression of least privilege.

Group-based access

Breaks: per-user sprawl

Assign rights to groups and put users in them, rather than managing each user's access individually — scalable and auditable.

Protect /etc/shadow + strong passwords

Breaks: credential theft

Hashes live in shadow for a reason — restrict it, enforce a password policy, and salt/hash properly (the crypto lab's point applied to logins).

sudo, not root login

Breaks: unlimited standing privilege

Grant elevated rights through sudo for specific tasks instead of logging in as root. Limits standing privilege and leaves an audit trail.

Remove/disable unused accounts

Breaks: forgotten doors

Dormant accounts are a classic attack path. Disable or delete accounts for people and services no longer active.

Sensible umask

Breaks: risky defaults

A good default umask means new files aren't created over-permissive in the first place — least privilege by default.

⚡ Cheat sheet

Who, and what.

Commands

  • groupadd HR · useradd jenny · passwd jenny
  • chmod u+rwx · g-rwx · o+r
  • chmod 764 (rwx rw- r--)
  • ls -l to read it back
  • Accounts: /etc/passwd · hashes: /etc/shadow

Do it right

  • Least privilege everywhere
  • Group-based access
  • Protect /etc/shadow; strong passwords
  • sudo, not root login
  • Remove unused accounts; sane umask

Octal cheat

  • r = 4, w = 2, x = 1
  • 7 = rwx · 6 = rw- · 5 = r-x · 4 = r--
  • Order: owner · group · others
  • Directory needs x to enter

✅ Check yourself

1. Translate chmod 764 file into who-can-do-what.

Owner = 7 = read+write+execute (rwx); group = 6 = read+write (rw-); others = 4 = read only (r--). So -rwxrw-r--.

2. Symbolic (u+rwx) vs absolute (chmod 755) — do they do the same thing?

They control the same permission bits in different notations. Symbolic adjusts specific bits for specific classes (add/remove), while absolute sets all three classes at once to an exact value. Same model, two ways to express it.

3. Where are Linux password hashes stored, and why not in /etc/passwd?

In /etc/shadow, which is readable only by root. /etc/passwd is world-readable and lists account info, so keeping hashes out of it prevents ordinary users from grabbing them to crack offline.

4. What security principle do these users, groups, and permissions ultimately enforce?

Least privilege — each account and file is granted only the access it genuinely needs and no more, which limits what any compromised account or mistake can reach.
