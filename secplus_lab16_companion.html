Securing Data with Encryption Software

A laptop gets stolen; a USB drive is lost. Whether that's a breach or a shrug comes down to one thing — was the data encrypted at rest? This lab builds an encrypted VeraCrypt container and shows what that protection does and doesn't cover.

📋 Overview

Encryption at rest, demystified in one container.

VeraCrypt creates an encrypted container — a single file that, when mounted with the right passphrase, behaves like a normal drive, and without it is indistinguishable from random noise. You'll create one, put files in it, dismount it, and see that the data is only readable while mounted. This is data-at-rest encryption: protection for information sitting on disk, as opposed to data in transit (Lab 22) or in use.

[THE ONE IDEA] The passphrase is the key. Encryption strength is irrelevant if the passphrase is weak or lost — a strong cipher with a guessable password protects nothing, and a strong password you forget protects the data even from you.

Create the vault, fill it, lock it.

Task 1

Creating a VeraCrypt Container

Task 1.1

Creating a Container

In this task, you will configure an encrypted volume container on the Kali Linux workstation.

1 Launch the Kali virtual machine to access the graphical login screen.

2 Log in as kali with kali as the password. Open the Kali PC Viewer.

3 Right-click on an empty space on the desktop, then select Open Terminal Here.

4 In the Terminal window, type touch billing.txt to create a text file.

5 Launch the VeraCrypt application by typing veracrypt in the Terminal window, followed by pressing the Enter key.

6 In the VeraCrypt application window, click the Create Volume button.

7 Notice the VeraCrypt Volume Creation Wizard appears. Proceed with creating an encrypted file container by selecting the radio button for Create an encrypted file container and clicking Next.

8 On the Volume Type step, select the radio button for Standard VeraCrypt volume and click Next.

9 On the Volume Location step, click on the Select File button.

10 A new File Manager window appears. Navigate to Desktop. Select the billing.txt file and click Save.

11 When asked to replace the file, click on Replace.

12 Back on the VeraCrypt Volume Creation Wizard window, verify that /home/kali/Deskop/billing.txt is prefilled in the Location field and click Next.

13 On the Encryption Options step, leave the default set to AES and SHA-512. Click Next.

14 On the Volume Size step, enter the value of 50. Verify MB is selected and click Next.

15 On the Volume Password step, type password and confirm the password of password. Click Next.

16 When prompted with a warning, click Yes to continue.

17 On the Format Options step, leave the default set to FAT and click Next.

18 On the Volume Format step, the VeraCrypt software will collect the mouse movement as a factor for generating the encryption key, so keep moving your mouse at this screen until you are satisfied with the Randomness level (shown in blue). Then, click Format.

[NOTE] The higher the randomness, the securer the encryption.

19 When prompted with a warning message, click Yes to replace the billing.txt file with a Veracrypt container.

20 Click OK in response to the successful operation message.

21 Click Exit on the Volume Created screen to exit the VeraCrypt Volume Creation Wizard window.

22 Leave the VeraCrypt application open to continue with the next task

Task 2

Opening and Viewing Data within a VeraCrypt Container

Task 2.1

Using the VeraCrypt Container

1 While on the Kali system with the VeraCrypt application opened, click on the Select File button to locate your VeraCrypt container.

2 A new File Manager window appears. Navigate to Desktop and select the billing.txt file. Click Open.

3 Select one available drive slot from the list and then click on the Mount button.

4 When prompted for a password, type password and click OK.

5 When prompted for Administrative privilege enter kali. Then click OK.

6 Notice that the drive is now successfully mounted when looking at the VeraCrypt window with the mount directory information presented as /media/varecypt1. There should be a drive appearing on the desktop.

7 Notice the steg folder on the desktop; double-click to open it. You should see two pictures. Press Ctrl + A to select them, then right-click on the file and select Copy (or simply Ctrl + C ).

8 Click on the veracrypt1 52MB Volume located on the left menu pane.

9 Right-click in the white space and select Paste. (or Ctrl + V to paste)

10 Close the File Manager window.

11 Change focus back to the VeraCrypt application window. Click on the Dismount button to unmount the veracrypt1 volume

⚠️ Where students get stuck

The handful of gotchas.

[FORGOTTEN PASSPHRASE = GONE] There is no recovery. A lost passphrase means the data is unrecoverable by design — that's the feature working, not a bug. (Enterprises solve this with key escrow/recovery agents, not back doors.)
[MOUNTED = EXPOSED] While the volume is mounted, its contents are decrypted and readable by anyone at that session. Protection only applies when it's dismounted — lock it when you step away.
[GENERATING RANDOMNESS] The wizard asks you to move the mouse to gather entropy for the key. Rushing this weakens the key — keep moving until the bar fills.
[FORMAT ERASES] Creating the volume formats it. Point it at the right location/size so you don't overwrite something you meant to keep.
[CONTAINER vs FULL-DISK] This is a file container, not full-disk encryption. It protects what's inside it — not the rest of the system, temp files, or swap.

🛡️ The defender's view

Encryption at rest is the control; these make it actually work.

Full-disk encryption

Breaks: lost/stolen devices

Container encryption protects one vault; FDE (BitLocker, LUKS) protects the whole device — the enterprise standard for laptops and removable media.

Strong passphrase / key management

Breaks: weak or lost keys

The key is everything. Enforce strong passphrases, and manage keys centrally (escrow, HSM, TPM-backed) so loss doesn't mean data loss or a back door.

AES & modern ciphers

Breaks: weak crypto

Use vetted algorithms (AES) at adequate key length. Rolling your own or using deprecated ciphers undermines the whole exercise.

Encrypt at rest, in transit, in use

Breaks: partial coverage

At-rest is one state. Pair it with TLS in transit and, where needed, protections for data in use — a file is exposed somewhere in its lifecycle otherwise.

Secure deletion + key destruction

Breaks: residual data

Deleting the container, or destroying its key (crypto-shredding), renders data unrecoverable — cleaner than wiping every copy.

Back up the data AND the keys

Breaks: self-inflicted loss

Encrypted backups are only useful if the keys survive too. Protect and back up keys separately — this is where Lab 24 meets Lab 16.

⚡ Cheat sheet

Encrypt it at rest.

The build

  • Launch veracrypt
  • Create file container, AES, set size
  • Strong passphrase + gather entropy
  • Format the volume
  • Mount → use → dismount

Do it right

  • Full-disk encryption for whole devices
  • Strong passphrase; manage/escrow keys
  • AES / modern ciphers only
  • At-rest + in-transit + in-use
  • Back up data and keys

Know the terms

  • Data at rest — stored on disk
  • Container / volume — an encrypted file-drive
  • AES — the standard symmetric cipher
  • Key escrow — recoverable managed keys
  • Crypto-shredding — destroy the key to destroy the data

✅ Check yourself

1. A laptop with an encrypted VeraCrypt container is stolen while powered off. What has the thief got?

An unreadable blob. Without the passphrase the container is indistinguishable from random data, so the files are protected — this is exactly what data-at-rest encryption is for.

2. Same laptop, but stolen while the container was mounted and the user logged in. Now what?

The data is exposed — a mounted volume is decrypted and readable. At-rest encryption only protects data while it's locked/dismounted, which is why you lock devices and dismount volumes when away.

3. Why is 'the passphrase is the key' the most important idea here?

Encryption strength is irrelevant if the passphrase is weak (guessable) or lost (unrecoverable). The cipher protects nothing beyond the secrecy and strength of the key material, so key/passphrase management is the real control.

4. How does an enterprise avoid losing data when an employee forgets a passphrase, without creating a back door?

Through managed key escrow / recovery agents — keys are stored securely and centrally so authorized recovery is possible. That's different from a back door because access is controlled, audited, and tied to the organization's own key management, not a weakness in the cipher.
