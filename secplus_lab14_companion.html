Cryptography Concepts

Two ideas the exam keeps returning to, made concrete: steganography, which hides that a message even exists, and hashing, where changing a single bit of input scrambles the entire output. One is about secrecy of existence, the other about integrity.

📋 Overview

Two distinct concepts share this lab — keep them separate in your head.

Steganography hides a message inside something ordinary (here, a photo) so no one suspects a message is there at all. Hashing turns any input into a fixed-length fingerprint, and the lab shows its defining property — the avalanche effect — by flipping one bit and watching the whole hash change. You'll embed a secret with steghide, smuggle a zip inside an image by concatenation, and watch MD5/SHA-1 fingerprints transform in CyberChef.

[THE ONE IDEA] Steganography is not encryption. Hiding a message is security through obscurity; if someone finds it, they can read it. Encryption protects the message even when everyone knows it's there. The exam loves this distinction.

🧭 The walkthrough

Hide a message, hide a file, then watch a hash avalanche.

Phase 1 · Steganography with steghide

Put a secret inside a photo

kali@kali$ echo "The password to the WinOS is NDGlabpass123\!" > secret.txt kali@kali$ steghide embed -cf top_secret.jpg -ef secret.txt # cover file + embed file kali@kali$ steghide info top_secret.jpg # shows an embedded file exists kali@kali$ steghide extract -sf top_secret.jpg # pull the secret back out

-cf is the cover file (the innocent carrier), -ef the file to hide. steghide tucks the data into the image so it looks unchanged to the eye. A passphrase protects extraction — that passphrase is the only real secrecy; the hiding itself is just obscurity.

📸Screenshot for your report: the embed and extract succeeding (the recovered secret.txt).
Phase 2 · Hide a file by concatenation

A zip wearing an image's clothes

kali@kali$ zip secret_files secret.txt top_secret.jpg kali@kali$ cat cyber_monday.jpg secret_files.zip > cybersec.jpg

Because a JPG reader stops at the image's end marker and a zip reader reads from the end of the file, you can glue a zip onto the tail of an image. cybersec.jpg opens as a normal picture and unzips as an archive. Crude, but it illustrates how easily data hides in plain sight.

Phase 3 · The avalanche effect

One bit in, a whole new fingerprint out

kali@kali$ sha1sum top_secret.jpg # note the hash before

In CyberChef, build a recipe (From Binary → MD5, or SHA-1) and flip a single bit of the input. The output hash changes completely and unpredictably — that's the avalanche effect, and it's why a hash can detect even a one-character tamper. Re-running sha1sum on a changed file gives a totally different value.

📸Screenshot for your report: the hash before and after a one-bit change — two completely different values.

⚠️ Where students get stuck

Where this one trips people.

[STEGHIDE PASSPHRASE] embed and extract both prompt for a passphrase. Forget it and the secret is unrecoverable — the passphrase, not the hiding, is what actually protects it.
[-cf vs -ef] -cf is the cover (the carrier image); -ef is the file being hidden. Swap them and you'll embed the wrong way around.
[CONCATENATION ORDER] It's image first, then zip: cat image.jpg archive.zip > out.jpg. Reverse it and neither reader finds what it expects.
[HIDING ≠ ENCRYPTING] Don't walk away thinking you encrypted anything. Steganography conceals existence; without a passphrase or real encryption the content is readable once found.
[HASHES DIFFER EVERYWHERE] Your hash values won't match the lab's screenshots — they depend on your exact file. What matters is that a tiny change produces a wildly different hash.

🛡️ The defender's view

The concepts cut both ways — hashing is a defender's tool; steganography is a threat to detect.

Hash verification

Breaks: tampering / bad downloads

Comparing a file's hash to a published value proves integrity — one changed byte avalanches the hash. It's how you confirm a download or detect a modified file.

File integrity monitoring

Breaks: silent changes

Tools like AIDE/Tripwire baseline hashes of system files and alert on any drift — the avalanche effect is what makes this reliable.

DLP / stego detection

Breaks: data exfiltration

Steganography is a real exfil channel. Data-loss-prevention and stego-analysis tools inspect outbound files for hidden payloads and anomalies.

Strong, modern hashes

Breaks: collisions

MD5 and SHA-1 are broken for security use (collisions exist). For integrity-that-matters, use SHA-256+; the lab uses the old ones only to see the behavior.

Encrypt, don't just hide

Breaks: obscurity as 'security'

If data must be secret, encrypt it. Obscurity delays discovery but doesn't protect content — pair hiding with real encryption, or skip the hiding.

Salting (for passwords)

Breaks: precomputed attacks

When hashing passwords, add a unique salt so identical passwords hash differently and rainbow tables don't work — the exam's companion point to hashing.

⚡ Cheat sheet

Hide it, hash it, know the difference.

Commands

  • steghide embed -cf cover.jpg -ef secret.txt
  • steghide extract -sf cover.jpg
  • cat img.jpg files.zip > out.jpg
  • sha1sum file · md5sum file

What defenders use it for

  • Hash verification of downloads/files
  • File integrity monitoring (AIDE/Tripwire)
  • DLP / stego detection for exfil
  • SHA-256+ (not MD5/SHA-1)
  • Salt password hashes

Know the terms

  • Steganography — hiding that a message exists
  • Hash — one-way fixed-length fingerprint
  • Avalanche effect — tiny change, total output change
  • Collision — two inputs, same hash (bad)

✅ Check yourself

1. Steganography and encryption both protect a message. What's the fundamental difference?

Steganography hides the existence of the message (security through obscurity); encryption protects the content even when everyone knows the message is there. Hidden-but-unencrypted data is readable once discovered.

2. What is the avalanche effect, and why does it make hashing useful for integrity?

Changing even one bit of the input produces a completely different, unpredictable hash. That sensitivity means any tampering — however small — is detectable by comparing the file's hash to a known-good value.

3. Why shouldn't you use MD5 or SHA-1 for security-critical integrity today?

Both have known collision attacks — an attacker can craft two different inputs with the same hash — so they can no longer guarantee integrity. Use SHA-256 or stronger. The lab uses the old ones only to observe the behavior.

4. A download page lists a SHA-256 value next to the file. How do you use it, and what does a match prove?

Hash the downloaded file and compare it to the published value. A match proves the file wasn't altered or corrupted in transit (integrity). It does not by itself prove the source is trustworthy — that needs a signature.
