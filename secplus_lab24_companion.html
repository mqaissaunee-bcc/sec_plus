Performing Backups

Backups are boring right up until the moment they're the only thing that matters — after ransomware, a bad deploy, or a deleted file. This lab configures a Windows Server backup, then proves the part everyone skips: actually restoring.

📋 Overview

Resilience, made concrete — and tested.

Backups are the backbone of cybersecurity resilience: the answer to ransomware, hardware failure, accidental deletion, and bad changes. This lab installs the Windows Server Backup feature, schedules a backup to a local drive, then deletes a file and recovers it from the backup. That second half is the point — the industry's quiet truth is that untested backups fail exactly when you need them.

[THE ONE IDEA] A backup you have never restored is not a backup — it's a hope. The restore test is the control; everything before it is just copying files.

Task 1

Schedule a Windows Server Backup

In this task, you will set up and schedule a Windows server backup. Then you will customize the

Windows server backup to target a remote destination on the network.

1 Launch the WinOS virtual machine to access the graphical login screen. While on the splash screen, focus on the NETLAB+ tabs. Click the dropdown menu for the WinOS tab and click on Send CTRL+ALT+DEL.

2 Log in as Administrator using the password NDGlabpass123!.

3 Once logged in, click the search icon and type disk management into the search field. From the results, click on Create and format hard disk partitions.

4 If an Initialize Disk window appears, click Cancel.

5 In the Disk Management window, right-click on Disk 1 and select Initialize Disk.

[NOTE] Do note which disk is unallocated as this is the disk that you will want to initialize for this lab. The disk numbering may differ from the screenshot.

6 An Initialize Disk window appears, leave the defaults, and click OK.

7 Notice Disk 1 appears Online. Right-click on the Unallocated space for Disk 1 and select New Simple Volume.

8 A New Simple Volume Wizard appears, click Next.

9 For the next step in the wizard, leave the default value of 25597 MB and click Next.

10 Assign the drive letter E and click Next.

11 Rename the Volume label to Data and click Next.

12 For the last step in the wizard, click Finish. Notice a new useable partition is available. Close the Disk Management window.

13 Click the Server Manager icon to launch it. Click Add roles and features option.

14 In the Add Roles and Features Wizard window, in the Select installation type step, click the Next button.

15 At the Select destination server step, click Next.

16 At the Select server roles step, click Next.

17 At the Select features step, scroll down in the Features box until you see Windows Server Backup; click to check the Windows Server Backup feature, click Next.

18 At the Confirm installation selections step, click Install.

19 Wait until the installation finishes; click the Close button.

20 In the taskbar, click to open the File Explorer.

21 In the File Explorer window, double-click to open the Documents folder.

22 When you are in the Documents folder, right-click and select New > Text Document. Name it Important file.

23 Leave the window open, click on the search icon in the taskbar, and type windows server backup. Click the Windows Server Backup from the search result list.

24 Notice the wbadmin console windows appears. In the left pane, click on Local Backup. Notice the pane to the right changes, right-click on Local Backup in the left pane and click on Backup Once. If you don't see the option available, wait one minute for the application to finish initializing.

[NOTE] Normally you want to create a backup schedule. Because scheduled backups will happen on the hour, for time purposes, we will select the Backup Once option.

25 The Backup Once Wizard appears. On the Backup Options step, leave the default setting and click Next.

26 On the Select Backup Configuration step, select the radio button for Custom and click Next.

27 On the Select Items for Backup step, click on the Add Items button.

28 In the Select Items window, expand Local disk (C:) > Users > Administrator > Documents. Check the checkbox for Important file.txt and click OK.

29 Back on the Backup Once Wizard window, ensure that Important file.txt is listed and click Next.

30 On the Specify Destination Type step, select the radio button for Local drives and click Next.

[NOTE] Unless you are limited to access the local drive, you almost never want to backup to local drives. For this lab example, we are going to back up on the local drive.

31 On the Select Backup Destination step, change the Backup destination to Data (E:) and click Next.

32 On the Confirmation step, review the confirmation information and click Backup.

33 The backup will take 1-2 minutes to finish. When the status shows as Completed, click Close.

34 You will be brought back to the wbadmin window. Click the button to minimize it and continue to the next task.

Task 2

Recover the Lost File from a Backup

1 Switch back to the File Explorer with the Documents folder opened. Right-click on the Important file, press and hold the Shift key on the keyboard, and select Delete in the menu.

[NOTE] The Shift key will skip the Recycle Bin and directly delete the file.

2 A pop-up window will show, click Yes.

3 Switch back to the Windows Server Backup window, right-click on the Local Backup, then select Recover.

4 On the Getting Started step, make sure the radio button This server (WINOS) is selected.

5 On the Select Backup Date step, click Next.

6 On the Select Recovery Type step, make sure the radio button Files and folders is selected.

7 On the Select Items to Recover step, expand every folder in the Available items box and then select the Documents folder. Make sure the Items to recover pane has Important file.txt in it and select the file. Click Next.

8 On the Specify Recovery Options step, leave the default setting and click Next.

9 On the Confirmation step, click Recover.

10 When the Recovery Progress finishes, click Close. Then, close the Windows Server Backup window.

11 Switch back to the Documents window and notice that the deleted file is back.

12 The lab is now complete; you may end your reservation.

⚠️ Where students get stuck

What catches people out.

[FEATURE NOT INSTALLED] Windows Server Backup is a feature you add first. Without it, wbadmin / the console isn't there to configure.
[DESTINATION CHOICE] The backup needs a destination with room. The lab uses a local drive — fine for the exercise, but understand why that's not a real backup strategy on its own.
[SELECTING ITEMS] You choose what to back up. Back up too little and the restore can't help; the point is to include the file you'll later 'lose.'
[RESTORE IS THE LAB] Don't stop at a successful backup — the deletion-and-recovery is the whole exercise. A green 'backup complete' proves nothing until you restore from it.
[RECOVERY TAKES TIME] Restores aren't instant. Notice the duration — in the real world that gap is downtime, and it's what RTO measures.

🛡️ The defender's view

One restored file is the exercise; here's the strategy it points to.

The 3-2-1 rule

Breaks: single-copy loss

Three copies, on two media types, with one off-site. The lab's local backup is one copy on one medium — the rule is what makes backups survive real disasters.

Offline / immutable backups

Breaks: ransomware

Modern ransomware hunts and encrypts reachable backups. An offline (air-gapped) or immutable copy is what you restore from when everything online is encrypted.

Test restores regularly

Breaks: silent backup failure

Backups fail quietly — full disks, skipped files, corrupt media. Scheduled restore tests are the only proof they'll work, which is exactly what this lab practices.

RPO & RTO

Breaks: wrong recovery expectations

Backup frequency sets your recovery point (how much data you can lose); restore speed sets your recovery time (how long you're down). Design to the targets the business needs.

Encrypt & protect backups

Breaks: backup as a breach

Backups hold the same sensitive data as production. Encrypt them and control access — a stolen backup tape is a breach, and this is where Lab 16 meets Lab 24.

Backup types (full/incr/diff)

Breaks: time & storage trade-offs

Full, incremental, and differential trade backup speed/storage against restore complexity. Know how each affects RPO/RTO and the restore chain.

✅ Check yourself

1. Why is the restore step, not the backup step, the real test?

Backups fail silently — corrupt media, skipped files, wrong scope — and you only discover it when you try to recover. A successful restore is the only proof the backup actually protects you; an untested backup is a hope.

2. The lab backs up to a local drive. Give two reasons that's not a real-world backup strategy.

It's a single copy on a single medium (violates 3-2-1), and it shares the server's fate — fire, theft, or ransomware that reaches that drive destroys the backup along with the original. You need additional copies, off-site and ideally offline/immutable.

3. Define RPO and RTO and say what controls each.

RPO (recovery point objective) is how much data you can afford to lose, controlled by backup frequency. RTO (recovery time objective) is how long you can be down, controlled by how fast you can restore. Backups are designed to meet both targets.

4. Why is an offline or immutable backup specifically important against ransomware?

Modern ransomware actively seeks out and encrypts reachable backups before triggering. An offline (air-gapped) or immutable copy can't be altered or reached by the malware, so it remains a clean source to restore from when everything online is encrypted.
